# The AI coach

A text chat where a user asks gym and diet questions. **Text only and read only:** it cannot write to the log, change a weight or start a workout; "AI listens, code verifies" still holds. Decisions and reasons: ADR [017](../../docs/architecture/decisions/017-ai-coach.md) (the coach) and [018](../../docs/architecture/decisions/018-coach-second-provider.md) (the second provider). The prompt text is mirrored in [Gemini prompts](../../docs/ai/gemini-prompts.md): change both together.

## Behaviour

- **Persona:** the name is the single constant `COACH_NAME` (the header, the nav tab and the typing label all use it, and the prompt says the coach is an AI, not a person). The nav tab is labelled "AI Coach".
- **Gym and diet only, enforced three ways:** the prompt defines what is on topic (greetings, thanks and questions about the coach itself count, and are answered briefly); the model must answer `{onTopic, reply}` and the server trusts `onTopic` only to refuse, showing **our own** `COACH_REFUSAL` text; and a short exact prefilter (`coachScope.ts`) turns plain cases (sums, "solve ... =", weather, prices, code and poem requests) away before any model call. It never catches a gym question such as "write me a training program".
- **What the server does to a request:** cleans every turn (hidden and text-direction characters; earlier questions held to 500 characters), counts the limits (5 a minute, 20 an hour per user, scope `coach`), then the daily ceiling, then asks the model. A reply with a link, a code block or an HTML tag, an empty reply, or one not in the agreed form is not passed on.
- **Privacy:** the question and the last turns always go to the provider. A small anonymous summary of recent training (`buildCoachContext`: unit, up to three workouts as exercise names with set count, top weight and reps, the rule-based suggestion; no ids, email or timestamps, and the names of the person's own exercises are replaced by "Custom exercise") goes **only if the person turns the switch on; it starts off**. The notice (stored as seen under `next-rep-coach-notice-2`) says the free services may use the text to improve their products and names both providers.
- **The chat stays on the device** (`coachMessages`, newest 50, cleared at sign-out and by Clear chat; see [device-database.md](../local-data/device-database.md)). A question the coach could not answer is taken back out of the chat and returned to the box. Clear is disabled while a question is out.
- **Second provider (Groq):** `fallbackProvider.ts` speaks the OpenAI-style `/chat/completions` request over plain `fetch`. It is configured only when `FALLBACK_API_KEY`, `FALLBACK_BASE_URL` (https) and `FALLBACK_MODEL` are all set, and is asked **once** when Gemini throws, answers in an unreadable form, or the project's daily ceiling is used up (then Gemini is skipped). With both set up the timeouts are 12 s then 8 s (20 s for Gemini alone), and the second provider may use up to 1500 tokens because the model thinks first. Its answer goes through the same checks. Gemini's model is `COACH_MODEL`, else `GEMINI_MODEL`.
- **Answers are advice:** the prompt forbids diagnosis, drugs and crash diets, and never to invent a number; the person's facts arrive as JSON data and their text only ever as chat turns.
