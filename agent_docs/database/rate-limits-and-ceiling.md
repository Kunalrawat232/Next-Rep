# Rate limits and the daily ceiling

Added in migration `0005_rate_limit_scopes.sql` (applied 2026-10-18); tests in `tests/db/rateLimits.test.ts` and `tests/db/schema.test.ts`. The functions are called from the Vercel functions through `api/_lib/supabase.ts` (see [functions-and-handlers.md](../api/functions-and-handlers.md)).

| Piece                                                        | What it is                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| ------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `api_rate_limits`                                            | Per-user counters: primary key `(user_id, scope, window_seconds, window_start)`, plus `request_count`. Before 0005 the key was `(user_id, window_start)`, which let the minute and the hour collide and made `/api/parse` and `/api/coach` share one counter.                                                                                                                                                                                                  |
| `consume_rate_limit(p_scope text, p_window_seconds integer)` | `SECURITY DEFINER`, executable by `authenticated` only. Counts one request for `auth.uid()` in the current window and returns the new count. `p_scope` matches `^[a-z]{1,20}$` (the app uses `parse` and `coach`); the window is 1 to 3600 seconds; rows older than a day are deleted as it runs.                                                                                                                                                              |
| `consume_rate_limit(p_window_seconds integer)`               | The old one-argument form, kept so an older `/api/parse` keeps working; it counts as scope `parse`. Can be removed in a later migration once everything is redeployed.                                                                                                                                                                                                                                                                                         |
| `api_daily_totals`                                           | The project's model calls per UTC day: `(scope, day, request_count)`.                                                                                                                                                                                                                                                                                                                                                                                          |
| `consume_daily_ceiling(p_scope text)`                        | `SECURITY DEFINER`, `authenticated` only. Only scope `gemini` is accepted. Counts one model call and returns whether it is still within the day's ceiling, **1000 calls, fixed inside the function** (the caller cannot pass a maximum; change it in a new migration). It first counts a per-account cap of 100 calls an hour (scope `ceiling`); an account over the cap gets `false` without touching the shared count, so one account cannot use up the day. |

How the app uses them: each function counts the per-user limits first (parse 10 a minute and 60 an hour, coach 5 and 20), then the ceiling just before a model is called. When the ceiling says no, `/api/coach` uses the second provider if there is one, otherwise answers `limited`; `/api/parse` answers 429.

Open risk: signing up is open and "Confirm email" is off, so many accounts could still use up the daily ceiling for everyone; email confirmation and CAPTCHA (Supabase dashboard) are planned before the 25 Oct freeze.
