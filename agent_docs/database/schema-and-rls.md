# Schema and Row Level Security

Authoritative sources: `supabase/migrations/*.sql` (server), `src/domain/schemas.ts` (shared validation the app mirrors), [data model](../../docs/architecture/data-model.md). All weights are kg.

## Migrations

`0001_init.sql` (tables, constraints, indexes, RLS, the first rate-limit function), `0002_gym_bar_kind.sql` (bar kinds, name rules), `0003_exercise_muscle.sql` (exercise muscle), `0004_one_gym_per_user.sql` (one gym per user, `is_default` dropped), `0005_rate_limit_scopes.sql` (rate limits per endpoint, the daily ceiling). All five are applied to the hosted project. **Never edit an applied migration; add a new one.** Test schema and RLS with `npm run test:db` (PGlite loads the real migrations; `tests/db/`), and add a PGlite test for every change. `supabase/seed.sql` is **generated** from the two exercise JSON files by `npm run seed:generate`; never edit it by hand (`npm run seed:check` runs in CI).

## Tables

All have Row Level Security on. Policies are `to authenticated` and use `(select auth.uid()) = user_id` (`profiles` use `id`), with `with check` on writes. The `anon` role has no table access. Global exercises (`user_id` null) are readable by every signed-in user; writes are only on a user's own rows. Composite foreign keys `(x_id, user_id)` stop a row pointing at another user's gym or workout.

| Table                                 | Columns and rules                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `profiles`                            | `id` (references auth.users, cascade), `display_name` (up to 60), `default_unit` (`kg` or `lb`, default `kg`), `created_at`. One row per user, made by `ensureProfile` on sign-in.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `gyms`                                | `id`, `user_id`, `name` (not blank, default 'My gym', never shown), `default_bar_kg` (0 to 100, default 20: "the barbell"), `created_at`; `unique (id, user_id)`; **unique index `gyms_one_per_user`** on `user_id`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `gym_bars`                            | `id`, `user_id`, `gym_id` (composite FK, cascade), `name` (1 to 60, not blank, unique per gym ignoring case), `weight_kg` (0 to 100), `kind` (`ez_bar`, `smith` or `other`; at most one `ez_bar` and one `smith` per gym).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `exercises`                           | `id` (seeded ids are deterministic v5 UUIDs so offline sets can reference them), `user_id` (null = global), `name` (1 to 80, unique ignoring case among global rows and per user), `equipment_type` (barbell, ez_bar, smith, dumbbell, machine, cable, bodyweight), `body_part` (upper, lower, core), `aliases` (up to 20 items, 1000 bytes), `muscle` (one of 16 values, optional).                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `workouts`                            | `id` (minted on the device, no default), `user_id`, `gym_id` (composite FK, `on delete set null (gym_id)`), `started_at`, `ended_at` (`ended_at is null or ended_at >= started_at`), `notes` (up to 1000), `deleted_at` (soft delete); `unique (id, user_id)`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `sets`                                | `id` (minted on the device), `user_id`, `workout_id` (composite FK, cascade), `exercise_id` (FK; trigger `sets_check_exercise_visible` requires the exercise to be visible to the user), `total_kg` (0 to 500, **total including the bar**), `bar_kg` (0 to 100) and `per_side_kg` (0 to 250), both null when there is no bar, `input_mode` (`total`, `per_side`, `tap`; the app writes `total` or `per_side` and `tap` is unused), `reps` (1 to 100), `source` (`voice`, `tap`, `gemini`), `raw_transcript` (up to 500), `logged_at` (device time), `created_at` (server time, used for pull paging), `deleted_at` (the client never sends it in an upsert). Checks: `per_side` mode needs both bar and per-side values; `per_side_kg is null or bar_kg is null or total_kg = bar_kg + 2 * per_side_kg`. |
| `api_rate_limits`, `api_daily_totals` | See [rate-limits-and-ceiling.md](rate-limits-and-ceiling.md). RLS on with no policies: clients cannot touch them.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |

There is no routine, body-measurement or volume table.

## Adding to the schema

- **A new table or column the app syncs:** a migration with RLS policies; mirror the constraints in `src/domain/schemas.ts`; extend `RemoteLog` (`src/data/sync/types.ts`), the Supabase implementation (`src/data/remote/log.ts`), the fake (`src/test/fakeRemoteLog.ts`) and the local types (bump the Dexie version, see [device-database.md](../local-data/device-database.md)); add PGlite tests and update the data-model doc. Ask the developer first: it changes the data model.
- **A new exercise field:** a migration; update `ExerciseRowSchema` in `src/domain/exercises/catalog.ts` and the `Exercise` type; the mapping in `src/data/remote/exercises.ts`; if built-ins use it, the import script and JSON files, then `npm run seed:generate`; DB tests in `tests/db/exercises.test.ts`.
