# Test plan

Strategy and conventions: [testing strategy](../standards/testing-strategy.md). This plan lists what must be covered. Everything listed exists today unless a row says planned.

## Scope by area

| Area                                                                   | Cases                                                                                                                                                                                                                | Level                                                                                                                                                     |
| ---------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Weight maths                                                           | total from per-side, choosing a different bar of the gym, kg/lb conversion, rounding to 2 dp, dumbbell and bodyweight semantics                                                                                      | Unit                                                                                                                                                      |
| Validators                                                             | `total < bar`, jump check, confusables, ranges and the plate-achievability soft warning (values: `src/domain/validation/config.ts`, rules: [weight rules](../domain/weight-rules.md))                                | Unit (table-driven)                                                                                                                                       |
| Parser                                                                 | Number words and digits, units, rep markers, per-side markers, Hinglish and Hindi numbers 1–20, alias fuzzy matching, default to current exercise, all intents                                                       | Unit via `tests/fixtures/voice-phrases.json` (307 phrases)                                                                                                |
| Progression                                                            | increments by body part and unit, same weight on missed reps, a decrease after two misses at the same top weight, plate rounding, reason text (rules: [ADR-005](../architecture/decisions/005-progression-rules.md)) | Unit                                                                                                                                                      |
| Sync queue                                                             | enqueue, retry, idempotent upsert, workout before sets, failed state, offline → online                                                                                                                               | Unit (`fake-indexeddb`) + E2E                                                                                                                             |
| RLS (PGlite in `test:db`; hosted two-user checks run by the developer) | user A cannot select/insert/update/delete user B's rows on every table; global exercises readable by all                                                                                                             | Integration (hosted project, two users)                                                                                                                   |
| `/api/parse`                                                           | valid JSON, invalid JSON, 429, timeout, no token, bad token, oversized transcript, rate limit, daily ceiling, prompt-injection transcript                                                                            | Handler tests with fake Gemini (`api/_lib/parse.test.ts`)                                                                                                 |
| `/api/coach`                                                           | no or bad token, strict request schema, length and body caps, per-user and daily limits, off-topic prefilter, `onTopic` refusal, unreadable or unsafe reply (link, code, tag), Gemini failure then Groq, timeouts    | Handler tests with fakes (`api/_lib/coach.test.ts`, `coachScope.test.ts`, `fallbackProvider.test.ts`); live check by the developer: `npm run check:coach` |
| Components                                                             | `BreakdownCard`, `AmbiguityPrompt`, `SyncBadge`, `RestTimer`, the voice confirm card, the coach chat                                                                                                                 | Component                                                                                                                                                 |
| Core journey                                                           | sign in, start workout, tap-log a set, offline log then sync, view history                                                                                                                                           | Playwright smoke                                                                                                                                          |

## Failure scenarios (each becomes a test)

Built and tested: offline mid-workout; sync interrupted mid-batch; duplicate upload on retry; ambiguous total vs per side; browser evicts local storage; Gemini unavailable (parse and coach); Gemini down and Groq answers; microphone permission denied; Web Speech unsupported (Firefox); misheard number; browser recogniser silent on iPhone, switched to cloud speech-to-text (fakes, ADR-019; checked on an iPhone 15 in Safari and Chrome). Not testable: Supabase project paused.

## Exit criteria for submission

All must-have journeys pass; unit tests (`npm test`) and the database suite (`npm run test:db`, which holds the RLS tests) green in CI; the hosted integration suite (`npm run test:integration`) and the E2E smoke (`npm run test:e2e`) run by the developer, not in CI, and green; `npm audit` reviewed; RLS isolation test passing; no secrets in the history (gitleaks clean).
