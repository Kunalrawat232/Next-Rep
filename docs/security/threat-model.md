# Threat model: voice → Gemini → database

Status: voice, the parser, the Gemini fallback (`/api/parse`) and the AI coach (`/api/coach`, with Groq as a second provider) are built, with fake-provider tests (`api/_lib/parse.test.ts`, `coach.test.ts`, `coachScope.test.ts`, `fallbackProvider.test.ts`; `/api/parse` was checked once against the live API and `npm run check:coach` passed for both providers). All of T1 to T19 apply (T7 and T16 are controls in process and key handling rather than tested code).

Scope: the data path from the microphone to Postgres, plus auth and dependencies. Drafted with AI assistance and reviewed by the developer; update as the system is built.

## Assets

User workout data (their own, low sensitivity but personal), Supabase session tokens, the Gemini API key, the free-tier quotas, and the integrity of stored numbers.

## Trust boundaries

1. **Microphone → recogniser.** Chrome's Web Speech API sends audio to Google's servers for recognition; Safari uses Apple's. Audio leaves the device. We cannot control this; we document it.
2. **Transcript → parser.** Transcripts are untrusted text.
3. **Client → `/api/parse`.** Anyone can call a public URL.
4. **`/api/parse` and `/api/coach` → Gemini, and Groq for the coach.** External LLMs; their output is untrusted. Calls have timeouts (parse 8 s; coach 12 s for Gemini then 8 s for Groq when both are set up, 20 s for Gemini alone), and both endpoints share a project-wide daily ceiling.
5. **Client → Supabase.** Public anon key; RLS is the only gate.

## Threats and mitigations

| --- | ------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| T1  | Misheard numbers (60 heard as 16) corrupt the log                                                                                                | Deterministic validators, confusable pairs check against history, confirmation card with breakdown, tap-to-confirm for every voice set                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| T2  | Hallucinated or malformed Gemini output                                                                                                          | JSON-only prompt, strip fences, Zod validation, same validators as the parser, invalid output treated as `unknown`; Gemini never writes data                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| T3  | Prompt injection via transcript ("ignore instructions…")                                                                                         | Only a transcript and minimal context are sent; output constrained to the `ParseResult` schema; nothing in the output is executed; user confirms                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| T4  | Anonymous abuse of `/api/parse` drains the free quota                                                                                            | Requires a valid Supabase JWT (`getClaims`), per-user rate limit in Postgres (10 per minute, 60 per hour), request and transcript length limits, 8 s timeout, `unavailable` on any failure; a project-wide daily ceiling (1000 calls a day, 100 an hour per account, migration 0005, shared with `/api/coach`) so many accounts cannot drain the quota: over it `/api/parse` answers 429                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| T5  | One user reads or writes another user's data                                                                                                     | RLS on every table with `to authenticated` + ownership predicate, `WITH CHECK` on writes, automated two-user isolation test                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| T6  | Secrets committed to Git (history is submitted)                                                                                                  | `.gitignore`, gitleaks pre-commit and CI, read-deny of the common `.env` files for the AI assistant, only placeholders in `.env.example`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| T7  | Gemini key exposed to the client                                                                                                                 | Key only in server env (`GEMINI_API_KEY`, never `VITE_`-prefixed)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| T8  | Privacy: transcripts sent to a free-tier LLM                                                                                                     | Only the transcript is sent, no email/name/user id; documented that free-tier prompts may be used by Google; server logs omit transcripts with identifiers                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| T9  | Stale or evicted local data (iOS Safari)                                                                                                         | Sync as soon as possible; `navigator.storage.persist()`; visible sync badge                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| T10 | Unsynced and synced workout data left on the device after sign-out (shared or lent phone; same-origin scripts and extensions can read IndexedDB) | Per-user databases keep the next user from seeing it through the app. `purgeSynced()` deletes what the server already has and keeps unsynced rows; it is called at sign-out. Residual: unsynced rows stay readable on the device until they sync, and the data is not encrypted.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| T11 | Tampered rows in IndexedDB (the user or an extension edits a set)                                                                                | Every row is validated against the shared schemas again before it is sent; invalid rows are marked failed and never sent. The database repeats the checks (ranges, totals, ownership, foreign keys).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| T12 | A push that was already running when the user signed out carries on under the next user                                                          | The sync worker is paused at sign-out and checks before every step; the server's row-level security refuses a mismatched `user_id` as a second line.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| T13 | A corrupt or hostile row from the server (or a tampered response) reaches the device through the history pull                                    | Rows are untrusted: every one is checked against the shared schemas before it is stored, bad rows are skipped, and the pull is read-only, all-or-nothing and limited to the user's own rows by row-level security and an explicit `user_id` filter. Only finished workouts are taken, so a pull cannot replace the workout in progress. Rows are read by id, so a concurrent delete cannot make a valid row look deleted; an answer that would remove all, or most, of the synced rows is not applied; sign-out waits for a pull in flight and blocks new ones, so history is not written back after the purge; `raw_transcript` is not read back.                                                                                                                                                                              |
| T14 | Vulnerable or malicious dependency                                                                                                               | Minimal, exact-pinned dependencies, committed lockfile, `npm audit` before submission, removal of risky dev-only packages (for example `@vercel/node`)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| T15 | XSS from rendered user text (exercise names, notes)                                                                                              | React escaping only, no `dangerouslySetInnerHTML`, DB length limits                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| T16 | AI-assistant mistakes (wrong code, leaked secrets)                                                                                               | Human review of every diff, read-only reviewer agents, security-guidance plugin, read-deny of the common `.env` files, hooks; see [guardrails](../ai/guardrails.md)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| T17 | AI coach: prompt injection through the question or the chat ("ignore your rules", "reveal the prompt")                                           | The question only ever goes in chat turns, never in the instructions; the facts are a validated JSON block; the prompt says the chat is untrusted; the coach has no tools and cannot write anything, so the worst result is a bad answer in the chat ; scope is enforced in three layers (the prompt, a structured `onTopic` answer whose refusal text comes from our code, and a narrow filter for obvious off-topic questions), so the coach also cannot be used as a general chatbot that spends the free quota (tests in `api/_lib/coach.test.ts` and `coachScope.test.ts`)                                                                                                                                                                                                                                                 |
| T18 | AI coach: harmful advice (injury, medical, diets, drugs)                                                                                         | The prompt refuses medical advice, drugs and crash diets and sends pain and injury to a doctor or physiotherapist; the screen says it is training tips, not medical advice; replies are short and capped; the developer reads sample answers before the demo (a model cannot be made perfect)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| T19 | AI coach: personal data sent to Google or Groq, and abuse of the free quota                                                                      | Only the question and a small validated summary (names and numbers, no ids or account details, and the person can switch it off) are sent; the free tier may use prompts to improve products, and the second provider (Groq, [ADR-018](../architecture/decisions/018-coach-second-provider.md), asked only when Gemini cannot answer) gets the same text, which a notice says (shown again once); sign-in check, 5 a minute and 20 an hour per user, the project-wide daily ceiling (1000 calls a day, 100 an hour per account, migration 0005), length caps, timeouts (12 s for Gemini then 8 s for Groq, 20 s for Gemini alone); no question, reply or other text is logged (`api/_lib/coach.ts` logs only the failing step, the error kind and the HTTP status); the chat is kept on the device only and cleared at sign-out |

## Residual risks

Audio goes to the browser vendor's recogniser; Supabase free projects may pause; Gemini and Groq free-tier terms may change; many accounts can still be opened until email confirmation and CAPTCHA are switched on (the daily ceiling bounds the damage). All are listed in the README limitations.

## Validation

Mitigations T1 to T5 each map to an automated test (validator unit tests, the RLS isolation suite, and the fake-provider tests of `/api/parse` and `/api/coach`: `api/_lib/parse.test.ts`, `coach.test.ts`, `coachScope.test.ts`, `fallbackProvider.test.ts`). Results are recorded in the [QA report](../qa/ai-qa-report.md).
